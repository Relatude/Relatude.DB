More stars is better in every column: five stars goes to the best engine in it — the fastest, or the one holding the least memory — and every factor of ten behind that costs two stars, down to one. The number beside the stars is the geometric mean over that engine's runs (indexing: vectors indexed per second, including the state save; memory use: managed heap held after the load, so fewer MB earns more stars; search: Top10 queries per second), which is the average that suits values differing by factors. A verdict this compact hides the trade the charts below show: read them together.

How to read the charts

One chart per measurement. The X axis is the number of vectors indexed, the Y axis the measurement's own unit. Each line is one engine at one cache budget: colour is the engine, dash pattern is the cache budget — the tightest dashes are the smallest budget, a solid line the largest. Hover any point for its exact value.

engineMemoryIVSHNSW
cache10 MB50 MB100 MB

Every chart says under its title whether higher or lower is better, and the Y axes are logarithmic except for the percentages — the engines sit orders of magnitude apart, so on these axes an equal distance is an equal factor. A missing point is a failed or unsupported run, never a zero. The in-memory index has no cache budget to spend, so its dashed variants lie on top of each other by design: it is the reference the others are read against.
