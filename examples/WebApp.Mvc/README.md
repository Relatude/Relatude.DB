# WebApp.Mvc

> This folder is the reference for the `csharp_web_mvc` project type of `relatude new`. The command line tool
> carries the same files as a template (`src/Relatude.DB.Console/Templates/csharp_web_mvc`), fills in the name,
> namespace and package version, and writes a fresh `relatude.db.json`. Keep this folder and the
> template in sync: regenerate it with
> `relatude new WebApp.Mvc --out examples/WebApp.Mvc --force --projecttype csharp_web_mvc --package-version <v>`.

A website on [Relatude.DB](https://db.relatude.com): one ASP.NET Core MVC project with controllers,
Razor views and the database in the same process. Pages are rendered on the server, so every URL is
crawlable and carries its own title and description. Generated by
`relatude new WebApp.Mvc --projecttype csharp_web_mvc`; `relatude new --list-types` describes the other
project types, such as `csharp_web_react_ts` for an API with a React client.

```
WebAppMvc.csproj        ASP.NET Core MVC + Relatude.DB (C#, net10.0)
Program.cs                  app setup: Relatude.DB, MVC, static files, the default route
Controllers/                one class per area of the site; HomeController renders the start page
Views/                      Razor views; Shared/_Layout.cshtml is the page frame (title, description, nav)
Models/                     node classes in the namespace WebAppMvc.Models (see Models/README.md)
Middleware/                 serves files stored in the database by their URL
wwwroot/                    static files: css, images, scripts
relatude.db.json            database settings: where the data lives, which namespace holds the model
relatude.db/                the database itself, created on first start (git-ignored)
```

## Prerequisites

- .NET 10 SDK (`dotnet --version`)
- Optional: the Relatude.DB command line tool, `dotnet tool install -g Relatude.DB.Tool`

## Run

From this folder:

```bash
dotnet run --launch-profile https
```

Open <https://localhost:7238>. The first start creates the database in `relatude.db/`. If the
browser rejects the development certificate, run `dotnet dev-certs https --trust` once.

## The admin UI

<https://localhost:7238/relatude.db> browses and edits nodes, runs queries, shows the datamodel,
logs, backups and settings. On localhost no login is needed. To log in from anywhere else, set
`MasterUserName` and `MasterPassword` in `relatude.db.json`, or pass `--user` and `--password` to
`relatude new` next time.

## Add a node type

Create a class in `Models/`, in the namespace `WebAppMvc.Models`. It is a node type as soon as
the app restarts: `relatude.db.json` names that namespace as a datamodel source, so there is no
registration code and no migration.

```csharp
using Relatude.DB.Common;
using Relatude.DB.Nodes;

namespace WebAppMvc.Models;

[Node(TextIndex = BoolValue.True)]                       // the whole node is free-text searchable
public class Product {
    [PublicIdProperty] public Guid Id { get; set; }
    [StringProperty(Indexed = true)] public string Name { get; set; } = "";
    public string Description { get; set; } = "";        // no attribute needed
    [DoubleProperty(Indexed = true)] public double Price { get; set; }
    [BooleanProperty(Indexed = true)] public bool InStock { get; set; }
    [StringArrayProperty(Indexed = true)] public string[] Tags { get; set; } = [];
}
```

Only node types belong in that namespace: every class in it becomes a node type, so view models and
form models go elsewhere (for example `WebAppMvc.ViewModels`). `Indexed = true` makes a property
filterable, sortable and facetable. Adding properties later is fine. Renaming a type or a property
loses the data stored under the old name unless its id is pinned with an attribute;
`relatude validate` warns about that.

## Add a page

A page is a controller action plus a view. Controllers take `RelatudeDBContext` in their
constructor; `ctx.Database` is the database.

```csharp
// Controllers/ProductsController.cs
using Microsoft.AspNetCore.Mvc;
using Relatude.DB.NodeServer;
using WebAppMvc.Models;

namespace WebAppMvc.Controllers;

public class ProductsController(RelatudeDBContext ctx) : Controller {
    public IActionResult Index() {                       // /products
        ViewData["Title"] = "Products";
        ViewData["Description"] = "Everything we have in stock.";
        var products = ctx.Database.Query<Product>().Where(p => p.InStock).OrderBy(p => p.Name).Page(0, 50).Execute().ToList();
        return View(products);
    }

    public IActionResult Details(Guid id) {              // /products/details/<id>
        var product = ctx.Database.Get<Product>(id);
        ViewData["Title"] = product.Name;
        ViewData["Description"] = product.Description;
        return View(product);
    }

    public IActionResult Search(string q) {              // /products/search?q=wool
        ViewData["Title"] = "Search: " + q;
        return View("Index", ctx.Database.Query<Product>().WhereSearch(q).Take(20).Execute().ToList());
    }
}
```

```cshtml
@* Views/Products/Index.cshtml *@
@model List<WebAppMvc.Models.Product>
<h1>@ViewData["Title"]</h1>
<ul>
@foreach (var p in Model) {
    <li><a asp-action="Details" asp-route-id="@p.Id">@p.Name</a> &ndash; @p.Price</li>
}
</ul>
```

URLs follow the default route in `Program.cs`, `{controller=Home}/{action=Index}/{id?}`. Set
`ViewData["Title"]` and `ViewData["Description"]` in every action: the layout writes them into
`<title>` and `<meta name="description">`, which is what search engines read. `Get<T>(id)`,
`Insert(node)`, `Update(node)` and `Delete(id)` are the other calls you will reach for; writing
happens in controller actions that take a form post.

## Build for production

```bash
dotnet publish -c Release -o publish
```

One folder holds the whole site. Run it with `dotnet publish/WebAppMvc.dll`; the database folder is
created next to `relatude.db.json` in the content root, so keep that file with the published output.

## Inspect it from the command line

With the Relatude.DB tool installed, from this folder:

```bash
relatude schema                     # node types, properties and relations, as the engine sees them
relatude validate                   # what would break at startup, and what to worry about
relatude info                       # state, node counts per type, file sizes
relatude query "Product.Count()"    # any query, printed as JSON
relatude help all                   # the whole reference
```

`info`, `query`, `insert` and `delete` open the database, so the app must not be running at the same
time.

## Data and settings

- `relatude.db/` holds everything: transaction log, indexes, uploaded files. Stop the app and
  delete the folder to start over.
- `relatude.db.json` is the configuration. `DatamodelSources` names the model namespace,
  `WaitUntilOpen` makes the app wait for the database before it serves requests, `LocalSettings`
  holds caches, backups and index engines. `relatude settings` prints it resolved. Any value can be
  overridden by a `RelatudeDB` section in `appsettings.json` or by environment variables such as
  `RelatudeDB__MasterPassword`, which is where a real password belongs.
